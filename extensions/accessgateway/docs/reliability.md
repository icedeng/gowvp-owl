# 公网网关 P0～P2 可靠性改进

2026-11-12 已发布至 A `10.144.0.20` 与 B `121.37.88.13:6022`，实际产物、迁移和核验见 [发布记录](../../../deploy/releases/gateway-reliability-20261112.md)。遵循用户约束：只补报警文字和原始发生时间，不补现场抓拍/录像；同一授权网关按设备编码续接档案，不实施多网关迁移。既有迁移后端接口为兼容保留，详情页不再提供迁移操作。

## P0：报警持久化及安全续接

在线报警沿用 A 的持久收件箱：先提交收件箱再确认设备，保留原有国标业务应答、NOTIFY订阅校验及级联分发。控制连接不可用时，B 在报警语义和已认证设备 flow 绑定校验后，将文字记录原子写入私有 `state/alarms/`，文件 fsync、rename、目录 fsync 均成功后才回 SIP 200。失败/队列满不成功确认，设备是否重传取决于设备实现。容量为4096条/32MiB，单条16KiB，达到上限不挤掉未确认数据。首次新 A 成功拉取后才持久开启此功能，旧 A 不会被强制切换到新路径。补报只恢复事件数据，不补发旧 SIP 事务或旧业务通知。

A 每2秒分页拉取（每批64），在原设备/通道绑定与网关启用状态复核后，同一事件事务内落库，再确认对应ID；只有成功记录被删除，失败记录后续重试。重复报文和语义相同报警沿用事件核心去重与连续报警聚合。损坏文件保留并显式告警，后面的正常报警仍可补传；启动时只清除未提交的临时文件。不得手改或清空队列来消除告警。

断连期间收到、先于本次 A 连接或迟到超过15秒的报警标记为 `historical=true`，保留原始 AlarmTime 和 B received_at；不可解析的原始时间留在事件元数据，显示时间回退 B 接收时间。列表、卡片、详情均显示 **“历史补报、现场取证不可用”**。历史记录不创建现场取证任务，后台执行器和手工取证入口也再次拦截。既有实时记录重复补传仅去重，不篡改已经获得的证据。

信令安全边界：带 Note 签名的报警继续走原 SIP→A 验签链，不由 B 解析后直接确认；A 强制要求信令摘要验证时，不将文字队列接纳为业务事件；已积压文字保留，不会跳过验签消费。因此**这些签名/强制验签场景本轮不承诺离线文字补传**，仍依赖设备重传。不能为补传关闭验签或把未验证文字当成认证信令。

A 控制连接短暂中断时，B 保留仍在注册有效期内的认证设备 flow。A 根据设备编码找到原档案，并复核主体ID、同网关、B generation、原 flow、绑定版本、原注册有效期和最近90秒心跳；事务内再复核所有权与入口，刷新新 epoch。不得跨网关抢占，不延长原注册 TTL。成功后清除离线标记、加载原通道、重新查询目录并唤醒持久订阅恢复。通道以设备目录为准，不全部强制在线。

B 进程重启会生成新 generation，UDP flow/设备 TCP 连接不持久恢复，必须设备重新 REGISTER；报警队列仍保留。注册到期或 flow 心跳过旧同样等待设备重注册。实时播放/文件任务在控制恢复时回收旧资源，不承诺业务会话无中断续播。

## P1：故障闭环、恢复状态和链路诊断

详情运行监控显示最近连接恢复耗时、B 构建/协议版本、待补传数量和异常。设备区分网关未连接、网关恢复中、等待设备注册、设备离线和在线。耗时表示本次连接及恢复扫描时间，不等于全部厂商设备已上线。

网关故障以 `AccessGateway` 来源进入事件中心：控制断连、10分钟内3次抖动、报警补传异常/接近容量、资源清理积压、端口占用≥90%、证书30天内到期、近期媒体错误、队列压力≥6MiB、带宽≥配额90%。10秒采样、故障30秒防抖、恢复20秒防抖，故障身份和观测持久化，重试幂等；系统恢复自动完成未关闭事件，保留人工忽略/完成结果。采样由有效 A owner 执行，缺少监测源时保留状态。阈值本轮固定，不提供新增配置面板。

运维页可选择当前网关设备和通道执行真实链路诊断：SIP点播响应、B本地媒体首包、媒体WSS附着、A转发ZLM、ZLM可播放轨道以及资源回收。独立诊断会话和 stream 不停止已有普通直播；诊断超时/失败仍回收，清理失败明确列为待重试。未观测阶段显示未执行，旧 B 无首包能力显示需升级。诊断结果写管理员审计，不能用控制 probe 通过代替媒体链路通过。

## P2：受控代理和统一升级

`proxy_ref` 引用 A 凭据目录下 `proxies/<ref>.json`（目录0700、文件0600）。文件格式：

```json
{"url":"http://proxy.example.com:3128","username":"service-user","password":"REPLACE_SECRET","allowed_targets":["wss://gateway.example.com:8443/gateway/v1/control"]}
```

引用只允许字母数字、下划线和短横线，最长64；管理页面不接受代理 URL/密码。HTTP CONNECT 精确白名单覆盖控制、媒体、文件和 probe；每次校验目标全部 DNS 为公网并固定实际 IP，TLS 仍核对原域名、受信链和客户端证书。不读取 HTTP_PROXY/HTTPS_PROXY，不支持 SOCKS、任意内网隧道或跳过证书。HTTP代理到 A 的链路由组织网络保护，代理认证信息只发送给该代理。

统一发布 CLI、只读预检、兼容组合、摘要核对、备份、排空、分步升级和失败回退见 [发布工具](../../../tools/gateway-release/README.md)。运维审计只记录结果，不暴露远程执行能力。示例清单必须替换并审核，不能直接生产执行。

## 数据库和检查边界

数据库版本0.0.36增加事件历史字段、会话阶段时间和故障防抖表。停旧 A 并备份原库，执行 `OWL_DATABASE_DSN=... go run ./tools/accessgateway-migrate`，再运行相同命令加 `-check`。只补本轮事件字段，保留已有事件和媒体路径；可重复执行。SQLite/PostgreSQL迁移用事务，MySQL DDL失败可能已部分完成，应停服修复后重试。工具不改版本记录，新 A 正常初始化后记录版本。B 状态 schema 仍为1，新增报警目录独立保存。

自动化检查覆盖落盘/重启/容量/确认、历史禁止取证、重复补传、绑定撤销/续接边界、故障防抖恢复、受控代理与TLS、发布计划/回退逻辑。生产升级、生产库副本迁移、两端身份和设备恢复已核验；未执行真实断网报警补传、实际HTTP代理和诊断点播联调，前端页面效果由人工验收。统一发布 CLI 本轮仍只有本地逻辑验证，此次带首次数据库迁移的上线采用既有受锁发布流程。

人工验收重点：断开 A→B 后触发报警，重连只出现原时间的历史文字且无新增取证；A 重启设备编码/通道ID保持且订阅恢复，B重启后重注册；对指定通道诊断不影响已有直播、故障产生与恢复各收敛一次。
