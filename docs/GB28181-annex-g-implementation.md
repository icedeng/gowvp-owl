# GB/T 28181 附录 G 实现说明

## 1. 标准边界

附录 G 是“联网系统与其他系统接口的消息格式”，通过接入网关连接管理平台、综合接处警系统、卡口系统和其他城市信息系统。它不是普通 IPC/NVR 设备报警，也不是视频监控平台上下级级联的同义功能。

版本结论：

| X-GB-Ver | 标准档案 | 附录 G |
|---|---|---|
| `1.0` | GB/T 28181-2011 | 规范性附录，支持 |
| `1.1` | 2011 修改补充文件（2014） | 2014 未修改附录 G，继承 2011 |
| `2.0` | GB/T 28181-2016 | 规范性附录，支持 |
| `3.0` | GB/T 28181-2022 | 已删除，必须拒绝 |

依据：2011 第 6.9 条和附录 G（标准页 67-76）；2016 第 6.9 条和附录 G（标准页 99-108）；2014 修改补充文件未包含附录 G 修改项；2022 目录及正文不再包含该附录。

2011 和 2016 的附录 G 消息、字段必选性和顺序一致。两版 `ConfigDefence` 业务应答中的每个 `Info` 都限制为最多 1024 个字符。标准中存在多余空格、错误自闭合标签以及“5 种查询/6 种通知”与实际不同等排版问题；查询段写明“以下信息全部可选”，但个别字段漏写 `minOccurs=0`，实现按段落语义将查询过滤条件视为可选；列表类型的注释又要求 `AlarmRecord` 重复次数等于 `SendRecordNum`，实现据此允许 `SendRecordNum=0` 的空列表。实现按这些可判定语义建模，不复制错误 XSD 语法。

## 2. 消息和方向矩阵

| 根节点 | CmdType | 标准方向 |
|---|---|---|
| `Notify` | `MPAlarm` | 管理平台 → 综合接处警系统或其他城市信息系统 |
| `Notify` | `ECSAlarm` | 综合接处警系统 → 管理平台 |
| `Notify` | `TGSAlarm` | 卡口系统 → 管理平台 |
| `Notify` | `ConfigDefence` | 管理平台 → 卡口系统；`Type=true` 布控，`false` 撤控 |
| `Query` | `MPAlarmRecordList` | 综合接处警系统或其他城市信息系统 → 管理平台 |
| `Query` | `ECSAlarmRecordList` | 管理平台 → 综合接处警系统 |
| `Query` | `TGSAlarmRecordList` | 管理平台 → 卡口系统 |
| `Response` | 上述通知命令 | 与通知反向，携带原 `SN` 和 `OK/ERROR` |
| `Response` | 上述查询命令 | 与查询反向，携带原 `SN`、总数、发送数和对应记录列表 |

## 3. 当前代码状态

纯协议层位于 `pkg/gbs/annexg`，已经实现：

- 三类报警记录、布控/撤控、三类查询、三类列表响应和四类通知业务应答；
- 根节点、固定命令、正 `SN`、必选元素、元素顺序、重复/未知元素和简单文本校验；
- XML 解码同时限制为 1 MiB、最多 32 层和 100000 个节点，纯协议调用与 SIP 传输入口具有一致正文边界，拒绝深层或高节点 XML 的资源放大；
- `dateTime`、有限经纬度及列表计数一致性校验；
- `ConfigDefence/Response/Info` 的 1024 Unicode 字符上限；
- 2011/2014/2016 放行和 2022 明确拒绝；
- 管理平台、综合接处警、卡口、城市信息系统的消息方向校验；
- `Authorizer`、`Consumer` 以及按管理平台/接处警/卡口拆分的最小存储接口；`DomainConsumer` 只分派已授权消息，缺失对应领域能力时明确拒绝；零值适配器默认禁用；
- 消费方响应与原请求的命令、`SN` 和反向角色校验。

产品运行时位于 `pkg/gbs/annex_g_runtime.go` 和 `pkg/gbs/annexg/gormstore`，默认关闭，已经形成自动化代码闭环：

- 静态外部系统档案绑定系统 ID、唯一角色、`1.0/1.1/2.0` 版本、Digest realm/密码、可选独立 `Date + Note` seed、目标地址、UDP/TCP/TLS 传输、来源 IP/CIDR 和可选 TLS CA/双向证书；`3.0` 明确拒绝；RFC Digest 密码不允许使用普通设备的免鉴权占位符；
- 默认只允许 SIP-TLS，UDP/TCP 必须显式开启明文许可；入向报文同时校验来源、实际连接传输、唯一 `X-GB-Ver`、Content-Type 和带 nonce/nc 防重放的 RFC Digest，且不能借用普通设备 REGISTER 身份；全局信令摘要开启后，附录 G 按 `SignalDigestSeed → Password → Sip.SignalDigest.Seed` 选择 seed，在 SIP 业务中间件之前独立验签，不再误查普通设备凭据；
- 已通过认证的入向 MESSAGE 按外部系统使用独立令牌桶限流，默认 50 次/秒、允许突发 100；超限返回带 `Retry-After: 1` 的 SIP `503`，不会进入 XML 业务消费和数据库读写；
- 七类消息接入生产 MESSAGE 路由，先完成严格 XML、方向和授权校验；入向通知/查询先返回 SIP `200 OK`，再持久化并发送独立业务 `Response`，消费失败返回标准 `ERROR`；生产默认发送器已通过真实 TCP `MESSAGE → SIP 200 → 独立业务 Response → SIP 200` 串联测试；
- 管理平台报警、综合接处警报警、卡口报警使用独立 GORM 表幂等保存；三类查询执行时间/字段过滤并受单次返回上限约束；布控/撤控维护当前状态和不可变审计记录；
- `Server.AnnexGExchange` 支持管理平台主动发送 `MPAlarm`、`ConfigDefence`、`ECSAlarmRecordList` 和 `TGSAlarmRecordList`，复用 UDP 监听连接或按外部系统复用 TCP/TLS 长连接；主动请求和独立业务 `Response` 均通过事务级 `Date + Note` 签名器发送并校验 SIP 响应，SIP `401` 使用外部系统自己的 realm/密码重试、递增 CSeq、更换 Via branch并重新签名；全局摘要算法、编码、时间窗和开关热更新时同步刷新附录 G 安全器；
- 独立业务响应按“外部系统 ID + CmdType + SN”预登记和严格关联，未关联、重复或方向不符的响应返回 `409/400`；
- 主动交换在 SIP 写出前持久化原始请求及到期时间；调用方取消/超时和服务关闭只结束当前等待，不删除可能已经送达对端的关联。明确未发出的请求会先可靠删除持久化关联再删除内存关联；若数据库删除失败，则保留内存关联并把发送前错误与删除错误一并返回，避免内存/数据库分叉后重启恢复出静默残留。业务响应在返回 SIP `200` 前先持久化，随后幂等执行布控或查询记录副作用并删除关联；进程若在任一步骤崩溃，启动时恢复关联，并自动重放已持久化但未完成的响应副作用；
- 在途关联默认保留 24 小时、最多 4096 条，可配置为 `1m–168h` 和最多 10000 条；启动、写入和随生命周期运行的清理器共同删除过期记录，防止内存和数据库无界增长；
- `/gb28181/metrics` 输出附录 G 入向请求、鉴权受理、拒绝、限流、业务失败和当前在途数量，可由部署侧据此设置失败率、限流量和积压告警；
- 管理端提供 Bearer 鉴权保护的业务审计查询：`GET /gb28181/annex-g/alarms` 查询 `mp/ecs/tgs` 三类报警完整记录，`GET /gb28181/annex-g/defences` 查询布控当前状态，`GET /gb28181/annex-g/defence-audits` 查询不可变的布控/撤控历史；三者均支持业务字段、RFC3339 时间范围和分页过滤，默认每页 50 条、最多 500 条，避免审计读取无界占用数据库和内存；
- `MPAlarm` 发送前保存本地记录；`ConfigDefence` 只在远端返回 `OK` 后提交本地布控状态和审计；ECS/TGS 查询成功后把记录幂等落库。

运行时配置示例；该配置包含身份、连接和存储运行态，修改后需要重启：

```toml
[Sip.AnnexG]
Enabled = true
MaxSendRecords = 100
InboundRate = 50
InboundBurst = 100
PendingTTL = '24h'
MaxPending = 4096

[[Sip.AnnexG.Systems]]
ID = '34030000002000000001'
Role = 'emergency_command_system'
Version = '1.0'
Password = 'replace-with-secret'
SignalDigestSeed = 'replace-with-independent-note-seed' # 可选；为空依次使用 Password 和 Sip.SignalDigest.Seed
Realm = '3403000000'
Address = 'ecs.example:5061'
Transport = 'tls'
SourceCIDRs = ['192.0.2.0/24']
AllowInsecureTransport = false
TLSCA = './configs/certs/ecs-ca.crt'
TLSServerName = 'ecs.example'
```

附录 G 标准本身定义的是外部系统消息格式，没有强制规定 Owl 必须使用 SIP MESSAGE。当前 SIP MESSAGE、Digest、TLS 和连接管理是 Owl 的接入网关实现选择，互通时仍应以目标综合接处警/卡口网关的实际传输约定为准。

## 4. 仍需完成的生产验收

以下项目仍是“前三版完整附录 G 生产支持”的必要条件，不能用自动化代码链路代替：

1. 至少一个真实综合接处警系统、一个真实卡口系统及一个城市信息系统的双向互通矩阵；
2. 对端断线、DNS/证书轮换、SIP 重传、业务响应迟到/重复和真实进程重启恢复演练；代码已持久化在途请求及响应并自动恢复/重放，但仍需验证目标数据库、真实对端重传策略和重启窗口；
3. 真实权限数据范围、部署侧指标告警规则和敏感凭据管理；代码已提供 Bearer 鉴权保护的业务审计查询、每外部系统调用限流及指标原始数据，仍需在目标环境接入实际用户角色和数据权限；
4. 大批量记录、并发请求、长连接抖动及恶意 XML/SIP 流量下的目标环境容量和安全测试；代码已具备 XML 字节/深度/节点限制、SIP 传输上限、每外部系统限流、有界查询和对应自动化边界测试；
5. 目标环境灰度、回滚和正式检测认证。

实现继续放在同一仓库的独立协议/领域模块中，无需另起项目。只有当团队、部署、数据权限或故障域必须独立时，才建议把现有适配边界迁为独立服务。

## 5. 验收口径

- `pkg/gbs/annexg` 测试通过，只能声明“附录 G 纯协议层完成”；
- 静态身份、生产路由、存储、主动连接器和响应关联测试通过，可声明“自动化代码链路完成”；
- 真实外部系统矩阵、安全/性能测试和目标环境灰度完成后，才能声明“生产支持完成”。
