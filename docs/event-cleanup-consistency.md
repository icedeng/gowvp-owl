# 事件清理与附件一致性

自动过期清理和手工删除现在使用同一套删除事务：先锁定事件，重新核对保留期及取证状态，再原子删除事件、报警明细、处理记录和取证任务，同时保存附件清理任务。数据库事务提交之前不删除文件。

## 文件清理与失败恢复

新增 `event_media_cleanup_tasks` 表，保存被删除事件的图片、视频相对路径，以及失败次数和最后错误。该表不以事件为外键级联删除。记录存在即表示尚未完成文件清理。

- 删除事务失败或影响行数异常：回滚事件及任务，保留证据文件。
- 数据库删除成功后进程退出：任务仍在数据库中，重启后继续清理。
- 文件或缩略图删除失败：保留任务，后台每分钟重试。一个失败任务不会阻塞后续任务。
- 文件已删除、清理任务提交失败：下次把已不存在的文件视为成功，再删除任务，因此重试安全。
- 文件仍被其他事件引用：暂缓删除。最后一个引用解除后再回收。
- 根目录不可访问、路径越界、父目录为符号链接或目标不是普通文件/链接：保留任务并记录错误；不递归删除目录，也不扫描删除无任务的文件。请修复目录权限、挂载或历史错误路径后等待重试。

原图和缩略图继续通过现有互斥机制删除，避免按需生成缩略图与删除互相覆盖。空目录不再递归清除，以免干扰并发取证创建目录。证据仍位于既有 `configs/events` 根目录，相对路径应保持唯一且不复用已删除证据的路径。

手工删除返回成功表示数据库事件已删除；文件可能因故障稍后回收。任务可用以下只读 SQL 检查：

```sql
SELECT id, event_id, attempts, last_error, created_at
FROM event_media_cleanup_tasks
ORDER BY id;
```

## 并发与取消

取证入队、领取和事件删除使用相同的事件行锁，再操作取证任务。自动清理在候选查询后仍会在事务内重新检查，`queued`、`working` 任务不能被删除。现有实时取证窗口及保留天数规则不变。

候选按 ID 每批读取 100 条，逐事件短事务删除，避免长时间锁住整批事件。相较旧批量删除，数据库往返次数增加；大量历史积压需要关注清理耗时。保留期清理仍在启动时及每 24 小时执行，已提交的附件任务在启动和每分钟重试。

调用方的 context 传入查询和删除事务，并在批次及文件之间检查取消。停服后未完成的附件任务保留，不会为完成文件清理重新建立无期限的后台 context。本地文件系统操作本身不支持中途取消。

## 数据库升级和边界

本次增加一张任务表，以及 `events.image_path`、`events.video_path` 的查询索引，避免共享引用检查反复扫描整表；不改变已有事件字段和状态。已加入现有事件 AutoMigrate 和 SQLite 到 PostgreSQL 迁移工具的模型清单，并将数据库版本递增为 `0.0.35`，使已有 `0.0.34` 部署首次升级时执行迁移。发布时须按当前部署的迁移流程创建新表及索引；关闭自动迁移的环境应先完成表结构升级。大表建立索引的耗时和锁影响须纳入发布窗口。若缺表，带附件的删除事务会失败并保留事件及文件，不会退回旧的先删文件逻辑。

不要直接清空任务表，否则会丢失尚未完成的文件回收记录。回滚到旧版本不能继续消费新任务；需要协调版本及数据库备份，不能把尚未回收的文件误认为无关垃圾。

验证使用临时 SQLite 数据库和测试文件，覆盖删除回滚、零影响行、取消、缺表恢复、进程重启、共享文件、文件删除失败、任务提交失败、取证状态变化及越界路径。PostgreSQL 时间参数有定向 SQL 测试；未执行生产数据库、真实摄像头联调或大规模清理压测。
