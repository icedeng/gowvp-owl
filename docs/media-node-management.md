# 媒体节点管理

管理端「媒体节点」支持新增、编辑、启用、停用和删除；详情页的「管理节点」可直接打开对应节点的编辑窗口。

## 接入参数

- 节点标识：1–64 位字母、数字、下划线或短横线，以字母或数字开头，创建后不可修改；`local` 为默认节点保留标识。
- 类型：ZLMediaKit 或 Lalmax，复用现有媒体驱动。
- API 地址和端口：平台访问媒体服务的 HTTP API 地址；地址不包含协议和端口。同一地址、端口不能重复接入。
- 平台回调地址：媒体服务能访问的平台 IP 或域名，端口使用平台服务的 HTTP 端口。
- SDP 收流地址：摄像机可访问的媒体节点地址；留空使用 API 地址。
- RTP 端口范围：例如 `30000-50000`，遵循现有驱动的端口分配规则。
- API 密钥：必须与媒体服务配置一致；编辑时留空保留已有值，响应不会返回密钥。

新增或启用后立即连接；失败时保留离线节点并由现有心跳检查继续重连，管理端可修改连接参数。连接时沿用现有驱动逻辑，同步平台需要的媒体节点标识、回调和收流参数；这不提供 ZLM 任意配置编辑器。

## 操作边界

- **停用**：持久保存停用状态，停止自动重连和接收节点回调，拒绝新的收流、代理、RTP 发送、录像启动及平台媒体访问。保留通道绑定，已绑定通道不会自动切换节点。不会停止远端 ZLM/Lalmax 进程。
- **启用**：重新连接媒体节点；连接失败显示离线，继续自动重连。
- **编辑**：存在活动通道、媒体流或 RTP 接收端时拒绝编辑，避免连接参数变更影响正在使用的会话。
- **删除**：`local` 无论状态如何都禁止删除。其他节点须先停用，再解除全部通道绑定，且不存在活动通道；只删除平台的连接配置，不删除远端录像、图片或容器。
- **空闲检查**：在线 ZLM 节点会查询媒体流及 RTP 服务；查询失败时拒绝修改/停用。节点离线时仍检查平台通道的活动状态。
- **回调隔离**：新回调 URL 携带 `media_server_id`，按对应节点的独立密钥校验，并核对回调体中的 `mediaServerId`。兼容不带节点参数的旧 `local` 回调；节点重启仅将该节点上的 RTMP 通道标记离线。

本次管理功能不引入自动负载均衡或故障切换；各协议继续沿用已有节点选择能力。国标通道可在通道详情中绑定节点，停用节点不可作为新绑定目标。

## 管理接口

全部接口沿用管理端登录鉴权。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/media_servers` | 节点列表，含 `disabled` 与运行状态 `status` |
| POST | `/media_servers` | 新增节点 |
| GET | `/media_servers/:id` | 脱敏详情 |
| PUT | `/media_servers/:id` | 编辑连接参数 |
| PUT | `/media_servers/:id/state` | `{"disabled":true}` 停用，`false` 启用 |
| DELETE | `/media_servers/:id` | 删除已停用、无绑定的非 local 节点 |

新增请求示例：

```json
{
  "id": "edge-zlm-1",
  "type": "zlm",
  "ip": "192.0.2.20",
  "http_port": 8080,
  "hook_ip": "192.0.2.10",
  "sdp_ip": "192.0.2.20",
  "secret": "your-node-api-secret",
  "rtpport_range": "30000-50000"
}
```

数据库结构版本升级到 `0.0.30`，新增 `media_servers.disabled`，非空且默认 `false`，现有节点保持启用。沿用现有版本检测及 AutoMigrate 流程；迁移失败会阻止初始化，不跳过失败继续运行。`local` 的连接参数仍同步保存到配置文件，停用状态由数据库保存，服务重启不会恢复为启用。
