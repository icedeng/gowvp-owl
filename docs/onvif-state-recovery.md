# ONVIF 状态并发与失败重试

本次修改针对平台连接摄像头的 ONVIF 适配器，不涉及平台对外提供的 ONVIF 服务账号。修改仅在工作区，未部署、未连接真实摄像头。

## 实际行为

- 设备连接、成功心跳时间、状态提交、目录同步、凭据更新及设备删除使用同一设备操作锁。后台读取状态也需持锁，消除并发 Map 内对象字段的数据竞争。
- 设备在线状态及其通道在线状态在同一数据库事务内提交，按设备主键 `id` 定位。事务成功后才确认内存状态；设备或通道更新失败时保持待同步差异，下个状态检查周期继续重试，不依赖再次上下线。
- 首次探测失败也会提交离线状态，不再因心跳时间为零而一直跳过。正常成功心跳更新持久化的 `KeepaliveAt`。恢复在线只更新最近一次成功目录返回的通道，不把已从目录消失的通道重新标为在线。
- 后台每轮按唯一 ID 游标扫描数据库，最多 8 个并发探测；首次初始化失败、目录查询/保存失败、连接丢失和删除失败后的设备都能重新发现并重试。失败的 SDK 半初始化连接不会被缓存为可用连接。
- 用户编辑设备时，仍先验证地址与凭据再提交。验证或事务失败保留旧连接；提交成功后地址、用户名或密码发生变化才废弃旧连接。若提交后的初始化失败，配置保持已保存，后台使用新配置重试。日志会说明初始化失败；编辑成功不保证随后的每次网络请求也成功。
- 初始化、目录查询和后台任务在锁内重读当前数据库配置，迟到的请求不能恢复旧凭据或重建已删除设备。删除期间禁止后台写状态和目录；删除事务失败则按数据库中仍存在的设备重新连接。
- 心跳轮次结束后等待 30 秒再开始下一轮，成功心跳超过 70 秒视为离线；状态检查周期为 1 秒。首次启动立即开始探测。HTTP 单请求超时仍为 3 秒，实际轮次耗时取决于设备数量和网络情况，不承诺所有设备严格每 30 秒完成一次探测。
- 宿主退出信号会取消后台循环及 SDK 发出的 HTTP 请求；请求超时依然生效。设备操作采用固定 64 个分片锁，个别不同设备可能共用锁；正在执行的探测会让编辑或删除短暂等待。

## 发布影响

只需更新 Go 程序，无新增配置项、依赖或数据库迁移。重启后会重新探测设备并同步目录，失败设备会正确显示离线，恢复后再更新在线状态。已有设备配置和密码不需要格式迁移。

修改摄像头连接凭据后，新建 ONVIF 请求及获取的新播放地址使用新凭据；本次不主动中断已经建立的媒体代理会话。此项修复也不证明 ONVIF 厂商兼容性或大规模设备负载能力。

## 检查

本地 SQLite 与模拟 ONVIF 边界的 8 项回归及 race 检查通过，覆盖：

- 状态事务失败回滚，未发生新状态变化也能重试；主键与协议 ID 不同仍正确落库。
- 首次连接失败、目录保存失败、提交凭据后连接失败的自动恢复。
- 凭据提交生效、失败事务保留旧运行态、迟到初始化不恢复旧密码。
- 心跳与删除串行化，删除后不重建；删除失败后自动恢复连接。
- 并发心跳/状态检查无已检出的数据竞争；宿主取消信号传递到 SDK HTTP 请求。

现有 IPC 设备编辑/删除相关测试及 race 检查通过；API 与 app 包编译通过。依赖注入代码已使用仓库现有 Wire 版本重新生成。

尚需现场人工检查：摄像头断网后离线及恢复联网后上线；修改连接凭据后新请求可用；目录查询或心跳期间删除设备后不再出现设备或通道。以上未作为已通过的真实设备验收。
