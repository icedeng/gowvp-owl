# 通道抓拍与定时计划

## 使用入口

- **通道详情 → 抓拍与计划**：立即抓拍、按间隔定时抓拍，以及该通道的图片记录。
- **实时监控 → 抓拍**：展开当前通道的抓拍管理，实时视频可以继续播放。
- **平台运维 → 抓拍设置**：上传等待时间、FFmpeg 最大并发数，以及全平台抓拍记录。

立即抓拍先创建后台任务，界面显示排队或抓拍中；成功后自动打开原图。离开页面不会取消已提交任务，之后可以重新打开记录查看。失败显示具体原因，不返回旧封面冒充新图片。

图片记录支持预览、下载、重命名及删除。播放器未播放时以最新成功抓拍作为封面；播放中直接查看图片记录，不会用静态封面遮住视频。图片接口与管理接口使用相同鉴权。

## 方式与性能

按设备已保存的有效国标版本和能力直接选择方式：

| 条件 | 抓拍方式 |
| --- | --- |
| GB28181-2022（3.0），且未禁用 `snapshot` 能力 | 下发设备抓拍指令，接收设备 HTTP 上传 |
| 旧版国标或禁用设备抓拍能力 | 直接从该通道实时流使用 FFmpeg 取帧 |
| ONVIF、RTSP、RTMP 通道 | 直接从该通道实时流使用 FFmpeg 取帧 |

设备上传失败时不再按顺序尝试多种模式。若设备宣告 2022 但没有实现抓拍上传，可以在设备档案中禁用 `snapshot`，后续任务会直接取流。

实时流抓拍只启动一次 FFmpeg，取首个可解码视频帧；不再先运行 ffprobe、不固定等待 75 帧，也不关闭或重启正在观看的流。取帧本身最多执行 35 秒，取流任务（取得并发名额后，含启动）最多 60 秒，排队不消耗取帧超时。因抓拍建立的流沿用平台现有无人观看自动断流规则，手动录像不会被强制停止。

配置文件仍使用 `[Media]`：

```toml
[Media]
# 设备接受指令之后等待图片上传的秒数，默认 120；界面范围 1–3600。
GBSnapshotUploadTimeoutSeconds = 120
# 平台 FFmpeg 抓拍并发上限，默认 2；界面范围 1–32。
GBSnapshotFFmpegConcurrency = 2
```

在“抓拍设置”保存即写入当前 `config.toml`，新任务采用新值，无需重启。调低并发不会终止已执行任务；后续任务等待运行数降到新上限以下。设备上传等待不含下发信令的业务响应等待。

## 保存与删除

每次成功抓拍都持久化数据库记录和独立 JPEG 文件，不按天数自动清理，也不受录像保留天数影响。

- 数据表：`channel_captures`、`channel_capture_schedules`。
- 文件：`<ConfigDir>/cover/captures/<抓拍UUID>/<图片名>`。
- 默认文件名：北京时间的 `YYYYMMDDHHmmss.jpg`，例如 `20261105143025.jpg`。
- 每次抓拍使用不同目录，同一秒生成的图片不会互相覆盖。
- 图片统一保存为 JPEG（已有 JPEG 保留原图，其他支持格式转换）。管理端重命名会同时修改真实文件名；名称必须保留 `.jpg`，不能包含路径、冒号或控制字符。
- 删除先持久化“删除中”状态，再删除图片目录和记录；磁盘删除失败会保留状态并重试。已删除或失败任务的迟到上传不会重新创建图片。
- 删除通道或设备会停用相关计划、结束未完成任务，保留已有抓拍历史。全平台记录仍可查看这些图片。
- 升级前已有的临时封面继续兼容读取；此前被覆盖的旧图片无法恢复为历史记录。

Compose 现有 `cover` 挂载已覆盖子目录 `captures`，无需新增挂载。备份需要同时包含数据库及 `cover` 目录；永久保存的磁盘用量按实际抓拍数量增长。

首次启动新版将数据库版本升级到 `0.0.29`，创建两个新表及通道/时间、任务状态/时间、计划启用/下次执行时间索引，不改动已有通道和录像数据。迁移失败会阻止启动，修复数据库权限或空间后重试，不能跳过迁移继续运行。

## 定时计划

每个通道一条计划：启用开关、抓拍间隔（最少 10 秒，默认 300 秒），以及可选的首次执行时间。留空首次时间时，保存后等待一个间隔执行。计划与执行结果写入数据库，服务重启后继续。

调度器每秒检查到期计划，通过同一后台抓拍任务保存图片；同通道已有排队或运行任务时合并本轮请求，不重叠抓拍。停机期间错过的周期不逐次回补，恢复后只执行一轮，再从当前时间计算下一轮。重启会把被中断的运行任务标为失败，排队任务继续执行。

当前执行器用于单个 GoWVP 服务实例；多副本共享数据库时需另行实现执行租约，不能同时启动多个实例接管同一组计划。

## 接口

- `POST /channels/:id/captures`：异步创建任务并立即返回记录。
- `GET /captures?channel_id=&page=1&size=24`：分页历史记录（最大每页 100）。
- `GET /captures/:capture_id`：查询任务结果。
- `GET /captures/:capture_id/image`：查看原图；加 `download=true` 下载。
- `PUT /captures/:capture_id`，`{"name":"新名称.jpg"}`：重命名。
- `DELETE /captures/:capture_id`：删除记录与文件。
- `GET /channels/:id/capture_schedule`、`PUT /channels/:id/capture_schedule`：读写计划。
- `PUT /configs/info/snapshot`：保存上传等待秒数和 FFmpeg 并发。

原 `POST /channels/:id/snapshot` 保留同步兼容，也会永久保存图片，但可能超过调用方的 HTTP 超时；新调用方应使用异步任务接口。`GET /channels/:id/snapshot` 优先返回最新成功抓拍，没有时兼容旧封面。
